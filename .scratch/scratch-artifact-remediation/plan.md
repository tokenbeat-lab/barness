# 工单01实施顺序

1. 盘点普通测试对 scratch 文件、归档、脚本及子进程的传递依赖，记录固定哈希与 Git 跟踪状态。
2. 在独立、无忽略文件的 Git clone 对现有公共场景运行 RED，保留真实失败。
3. 逐切片交付 runtime 最小完整场景、原字节 Jev/Decisions ZIP 与必要 manifest；更新测试读取路径，旧历史原件不改。
4. 同一公共场景转绿；若完整受影响普通包发现其他缺输入，保留独立失败后补齐该缺口，不能 skip。
5. 固定最终代码与夹具后，在仅含已跟踪文件的全新工作区完成受影响普通包，核对 case 库存、audit、来源与输入集合。
6. 保存不可变回执索引及当前状态；普通验证交付与完整发布资格分开。

失败方式：缺/空/错归档、哈希/manifest/必需成员篡改、语义伪造、路径穿越/链接/超限、未跟踪输入、宿主目录隐式兜底。优先复用现有拒绝场景。

回滚：代码读取路径与新夹具成组回退；原件与失败回执保留。

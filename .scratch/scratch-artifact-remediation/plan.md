# 工单01实施顺序

1. 盘点普通测试对 scratch 文件、归档、脚本及子进程的传递依赖，记录固定哈希与 Git 跟踪状态。
2. 在独立、无忽略文件的 Git clone 对现有公共场景运行 RED，保留真实失败。
3. 逐切片交付 runtime 最小完整场景、原字节 Jev/Decisions ZIP 与必要 manifest；更新测试读取路径，旧历史原件不改。
4. 同一公共场景转绿；若完整受影响普通包发现其他缺输入，保留独立失败后补齐该缺口，不能 skip。
5. 固定最终代码与夹具后，在仅含已跟踪文件的全新工作区完成受影响普通包，核对 case 库存、audit、来源与输入集合。
6. 保存不可变回执索引及当前状态；普通验证交付与完整发布资格分开。

失败方式：缺/空/错归档、哈希/manifest/必需成员篡改、语义伪造、路径穿越/链接/超限、未跟踪输入、宿主目录隐式兜底。优先复用现有拒绝场景。

回滚：代码读取路径与新夹具成组回退；原件与失败回执保留。

## 工单02实施顺序

1. 固定活动文档原字节、Git版本、原链接基址与旧回执绑定；保存原状态。
2. 修正基础spec正文及Testing Decisions、追溯说明的现行/历史边界、公共合同的accepted ADR优先规则；地区README只保留当前暂停入口与历史快照导航。
3. 检查链接/锚点、旧文字取代范围、历史与暂停对象哈希、完整执行来源及旧选定输入变化；不把三份文档变化写成输入相等。
4. 提交文档，再保存独立doc-check及只读记录；不启动测试或恢复控制器。

## 工单03实施顺序

1. 固定全部独立脚本、压缩快照、旧状态/回执、封存入口及地区暂停对象的原字节；静态解析，不import被审查代码。
2. 追查Go公共测试/原生消费者与Python导入/子进程，区分活动消费者、合成测试、关闭轮次和暂停轮次。
3. 逐文件登记身份/理由、输入输出、写入/联网/厂商/构建/负载能力、适用源码/固定pin和替代入口；压缩源码单列。原件不写入。
4. 当前可编辑工具README导航到分类；封存README的旧命令只在外部说明历史身份，不改其哈希或重新执行。
5. 检查320项覆盖、字段完整性、引用、调用链、原件/暂停哈希和执行来源/选定输入差异，保存真实文档检查及只读判定。无新Go测试声明。

## 工单04实施顺序

1. 固定349处候选、原样快照、前轮状态/回执与地区暂停对象；旧输入与完整执行来源作为只读基线。
2. 按原链接语法/行号和已证实原基址分类；用原发布映射、相等Git blob或旧索引核对快照出处，无法确认的版本保持未知。
3. 在明确原件目录、有限Git历史及必要归档范围查找；核对原记录SHA后才登记找回，另外记录无原pin历史版本和未检索/超限范围。
4. 新增可阅读报告、逐候选处置、快照索引及恢复指针，不改封存正文、不续期任何授权或结论。
5. 检查覆盖/引用/指针哈希/保护对象/来源输入相等性，提交文档并保存新不可变记录及只读报告；recovery7暂停，未执行阶段保持。

## 2. 组件与既有代码事实

- Host → catalog → ai；ai 不反向导入目录组件，维护工具不生产依赖内部 testkit。
- 现有 `Catalog.Hash()` 会先执行全目录校验，不能在剔除失败条目后用于核验完整输入。现有 `NewClient`、clone 与查询接口没有逐模型报告，本设计仍需实施。
- 单条临时 Catalog 可复用现有模型校验，但通用身份/路由接纳与重复组仍需在明确边界完成，不能误称已有 Hash 就覆盖全部条件。
- Kimi、xAI 等固定型号规则保持当前事实；实现时按真实协议能力和受控场景评估，不能笼统删除或只靠 JSON 解码放行。
- 现有错误可以区分认证、限流、网络等大类，不能可靠判定“必须升级”。报告及 Host 沿用允许公开的诊断边界，不透传未脱敏 SDK 原件。

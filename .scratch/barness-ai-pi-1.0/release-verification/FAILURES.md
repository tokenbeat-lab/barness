# 发布件核验的失败方式（实现前记录）

核验接缝沿用工单 02 与 ADR-0004：公开 npm 发布件、冻结 Git 源码、
依赖 lockfile、发布模型数据以及两者的完整 `dist/` 文件树。
每次运行在独立临时目录完成，不启用差分 oracle。

| 失败方式 | 必须拒绝的情况 |
| --- | --- |
| 错版本 | npm 元数据、安装副本或冻结源码中的 ai / telemetry 版本不是 1.0.0 |
| 未解释的源码差异 | tag、目标 commit、npm gitHead 不一致；本次输入预期三者相等，变化需重新调查而非自动放行 |
| 发布件损坏 | 下载字节的 SHA-512 与已固定 integrity 不符 |
| 缺模型数据 | 发布数据目录为空，或缺少预期文件（包括 `.manifest.json`） |
| 数据哈希错误 | 任一文件的 SHA-256、文件集合或完整模型数据哈希与固定输入不符 |
| 重建不等价 | ai / telemetry 的任一 dist 文件缺失、多出或字节不同；文件名与字节均比较，包含声明、map 与数据 |
| 依赖未锁定 | lock 缺失、哈希变化、安装改写 lock、外部包缺精确版本 / registry URL / integrity，或 ai / telemetry 未精确固定 |
| 构建失败 | 冻结源码的数据校验或 TypeScript 构建不成功；禁止用在线模型刷新修复 |
| 审计失败 | 输出材料包含凭据、主目录或主机名；只报告规则与文件，不回显秘密 |
| 下载超限 | 必须在读取中限额并取消响应，不能读完整响应后才检查大小 |
| 证据写入失败 | 即使磁盘写入失败，也必须释放临时源码、依赖与缓存；命令非零退出 |

任何失败使命令以非零状态退出，并生成明确的 FAIL 报告；不保留 PASS 状态。
重放必须重新安装和构建，不以旧报告代替实际核验。

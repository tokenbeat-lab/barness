### 2026-10-08：追加 ENOBUFS 诊断前的阶段记录

实现与完整材料见 [压力回环证据](../pressure-loopback-evidence/README.md)。新增公共
Client 循环直接复用原云端交互设计负载，每轮独立 fixture/Client/证据，首个失败即停止；
支持同进程、独立进程及完整套件后运行。32 路、负载、3 分钟截止、2 GiB 堆预算及全部
原失败断言不变。客户端底层读错误与 fixture 完成记录通过合成 requestId 关联，
包含已读/写字节、flush、取消与关闭状态，原始错误仅进入经审计的合成测试证据。

首次独立循环自然复现 1 路 `unexpected EOF`，发生于读取 2,522,281 字节后；完整 FAIL
包已保留。但该轮在补齐 fixture 生命周期及 requestId 诊断之前，不能据此归因。
它表明前序完整套件不是发生该症状的必要条件，不能证明本机网络波动。

另确认了妨碍重复诊断的测试基础设施缺陷：Run 长期保存 Case/testing.T，使 Go 1.26.2
已执行 cleanup 的闭包仍保留 Provider 请求捕获，约每轮 166 MiB。先添加跨轮公共负载
回归，实际第 14 轮超过原 2 GiB 预算后，才将 Run 改为完成时不可变摘要，移除对测试
句柄的持有。修复后同进程 100 轮 PASS（起始存活堆约 38–39 MiB）。这是独立确认的
内存保留修复，尚无证据将它与原 EOF 建立因果关系。

该阶段源码独立进程 10 轮 PASS；完整普通和 race 各 4,454 用例 PASS，均包含原压力、
冻结 pi 差分 623 用例及套件末尾 5 轮；两种 vet 与 live harness 元数据回归通过。
未发起真实厂商调用，因此本轮没有新的九组合 live 发布结论。所有失败历史保留，
该阶段全量受测源码保存逐文件哈希；审查见 [两轴报告](../pressure-loopback-evidence/REVIEW.md)。

当时第二、三项仍开放：诊断手段已补齐，原始读取中断的因果确认及对应回归尚未完成。
当时的后续目标是保留第一次带完整诊断的自然失败，按同一 requestId 对照读错误、fixture 写结果和
取消/关闭状态；不得用通过次数、受控 abort 或内存红灯代替该证据。


### 2026-10-08：追加自然失败确认 ENOBUFS，并先红后绿修复连接边界

最终关联诊断的追加循环在独立第一轮自然失败，15 路 `unexpected EOF` 全部按同一
requestId 对到 fixture TCP Write `no buffer space available`；客户端当时 context
未取消、BodyClosed=false，32 个 handler 完成记录齐全，3.20 秒结束，未到 3 分钟截止。
完整原包见 [ENOBUFS 自然失败](../pressure-loopback-evidence/history/write-buffer-interruption.tar.gz)。
这确认了本轮的直接原因：内核回环写缓冲 ENOBUFS 被 fixture 当成终止写错，HTTP 流
截断。没有证据将它归因于前序套件、跨轮内存累积、调用取消或计划 abort；也不能
追溯旧工单 17 九路的具体 errno，或推断宿主内核为何恰在该时刻耗尽缓冲。

先在公共 Client/真实 HTTP 栈前加入 socket 故障 fixture，七分支实际红灯 4 FAIL、
3 PASS，再在测试连接边界处理 ENOBUFS：每次 Write 最多等待 1 秒，以 1 毫秒间隔
仅续写未发送后缀；不重复帧、HTTP 请求或 AI Attempt。其他错误、持续耗尽、关闭、
截止/取消保持失败，等待次数按 handler 可观测；原压力负载、预算与失败断言不变。
回归变为 7 PASS，新增代码两轴审查无问题。修复后同进程 100 轮、独立进程 10 轮与
完整普通与 race 各 4,461 用例 PASS，两种 vet PASS。

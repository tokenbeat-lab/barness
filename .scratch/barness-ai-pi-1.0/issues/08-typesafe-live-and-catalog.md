# 08: 完成 TypeSafe 真实冒烟与目录纳入

**What to build:** 维护者能依据 TypeSafe 自己的真实 API 证据确认首批分类型号可用，并把固定版本、能力、费率与支持状态纳入目录及支持矩阵。

**Blocked by:** 06 — 完成 TypeSafe 评分、是非与原生 JSON 输入；07 — 验证 unary 调用的故障与资源释放。

**Status:** resolved

**依据：** 规格“分类：TypeSafe System One”“支持矩阵”“追溯与真实冒烟”、实施设计第 9.4–9.5、10、16 节，以及 ADR-0016/0017/0018。

- [x] 先列冒烟装置与报告可能误判的失败方式：未执行、缺凭据、错组合或操作、超预算、缺能力、漏脱敏、报告不完整，以及合并失败时部分写入；沿用现有装置验证方式后再扩展。
- [x] TypeSafe classifier 组合独立进程运行，只注入本组合低权限测试凭据和账户/区域别名；使用双开关、真实官方目标及固定 jev-1.13.0，限制调用和问题预算，报告实际调用、问题数、重试、用量与直连版本标识。
- [x] 真实冒烟覆盖三种问题混合、单选，以及预算内的 422 形状核验；检查 bool criteria 线上形状、版本化响应型号、厂商请求 ID、用量缺失语义及分布容差。每个结论来自本组合自己的证据。
- [x] 422 形状核验也经公共 Client：使用通过结构和宿主字节校验、但触发厂商 token 上下文限制的有界合成输入，记录预算和实际分类。空问题应由本地校验拒绝，作为离线失败场景覆盖，不增加绕过入口或另一个测试接缝；无法在预算内确认的真实形状明确记录为未确认。
- [x] 实施时重新读取官方能力、型号和价格事实，保存带官方来源与抓取日期的请求/响应和能力 fixture；首批只列固定版本 jev-1.13.0，输入按官方价计费、输出为零，别名不进入首期目录。
- [x] 支持矩阵与报告增加 operation 并核对操作、Provider、协议的一致性，六个旧组合明确为 chat。合并只更新本组合，错误或旧报告原子拒绝，NOT_RUN 不伪造 PASS 或覆盖有效历史。
- [x] 新增厂商请求 ID 与操作字段通过审计白名单审阅；证据包脱敏审计零发现，Observer 不含状态、问题、答案和错误正文。
- [x] 缺凭据或未执行输出 NOT_RUN，真实调用失败输出 FAIL，不以别名、替代型号或 UNSUPPORTED 代替必交能力通过；实际冒烟通过后才完成本工单和纳入支持声明。
- [x] 目录内容变化升版本、重建哈希与快照；修订协议 ADR、ADR-0010/0016/0017/0018、契约和追溯，交付可重放报告、审计与支持矩阵合并证据。

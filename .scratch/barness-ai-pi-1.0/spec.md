# barness-ai：对标 pi-ai 1.0.0 的增量规范

Status: ready-for-agent
Updated: 2026-10-07

本文是 barness-ai 从冻结基线 pi-ai `0.87.1` 升级到 `1.0.0` 的目标规范。它综合了同事的增量设计（2026-10-05）、对该设计的评审（2026-10-07）以及评审给出的解决方案，由维护者确认采纳。编码时的落点、精确规则、线上形状与失败场景见配套的[实施设计](design.md)；两者冲突时以本文为准。状态表示可据此拆分实施工单，不表示代码、协议兼容或真实 API 验收已经完成。本文沿用 [GLOSSARY](../../GLOSSARY.md) 的术语，并遵守 [docs/adr](../../docs/adr/) 中的既有决定；需要修订的决定在 Implementation Decisions 末尾逐条列出。

## Problem Statement

barness-ai 以 pi-ai 0.87.1 为冻结兼容基线，目前只支持一种模型操作：一次生成轮次的聊天调用，覆盖六个 Provider × 协议组合。pi-ai 已发布 1.0.0，带来两类变化：

- **新的模型操作。** pi 1.0 把图像生成和分类纳入统一的模型目录、Provider 与鉴权体系，各类模型有专属入口，误用会在运行时被拒绝。barness 的上层模块需要图像生成和结构化分类，但现在只能把它们伪装成聊天调用，或绕开 barness-ai 自行接入厂商，后者会失去租户隔离、凭据快照、资源限额、调用归属和错误分类。
- **聊天行为的修正。** pi 在 0.87.1 之后修正了几处聊天协议行为，例如看不懂的重试等待时间会立刻重试、加急档按标准价计费、未完成的工具调用被当作完成交出。barness 为保持 parity 照搬了这些行为，并用差分 fixture 和 ADR 锁定。只要基线停在 0.87.1，barness 就无法修正它们。

另外，pi 1.0 自身没有 OpenAI 或 Google 的原生图像接入，只有经 OpenRouter 的图像路线；barness 需要直连厂商。这部分没有 pi 行为可供对照，必须由 barness 自己定义契约并以厂商协议证明。

## Solution

barness-ai 的冻结 oracle 整体迁移到 pi-ai 1.0.0，四条聊天协议上的五项行为改为 1.0 的行为，并在新 oracle 下重新通过全量差分。

在此基础上，Client 从单一的聊天操作扩展为三种**模型操作**：chat、image、classifier。每种操作有自己的入口、模型类型、选项和结果；Binding 固定一种操作，旧的绑定只能做聊天。三种操作共享同一条调用管线：可信调用作用域、Binding 与凭据的一致快照、目录授权、准入、唯一的 HTTP 客户端、绑定上的重试策略、有限资源策略、可信回调、只含元数据的 Observer 以及 `(Result, error)` 契约。

首批交付三条新路线：

| 操作 | Provider × 协议 | 与 pi 的关系 |
| --- | --- | --- |
| classifier | TypeSafe × System One，型号 Jev | pi 1.0 有同一协议，请求编码与基本答案转换进入差分 |
| image | OpenAI × Images REST JSON | pi 没有，作为扩展路线登记 |
| image | Google × Gemini Interactions v1beta | pi 没有，作为扩展路线登记 |

原有六条聊天组合保持不变。

## User Stories

1. As a barness 维护者, I want 冻结 oracle 换成 pi-ai 1.0.0, so that barness 的兼容基线与目标版本一致，而不是永远落后一个大版本。
2. As a barness 维护者, I want 只保留一个冻结 oracle, so that 不必长期维护两套 runner、provenance 与账本。
3. As a barness 维护者, I want 新 oracle 按现有步骤重做等价核验并固定发布件哈希, so that 差分结果可以重复且不依赖研究目录。
4. As a barness 维护者, I want 受影响的差分用例逐条写明原行为、1.0 行为和依据, so that 评审者能看清每一处行为变化的来源。
5. As a barness 维护者, I want 内建目录与 pi 1.0 模型数据重新逐字段比对, so that 价格和型号能力不会悄悄偏离新基线。
6. As a 云端宿主开发者, I want 厂商返回无法解析的重试等待时间时按带抖动的指数退避等待, so that 一个格式错误的响应头不会让请求立刻重发、加剧拥塞。
7. As a 云端宿主开发者, I want 退避等待仍受绑定的上限和调用截止时间约束, so that 修正后的重试不会突破既有时限。
8. As a 计费负责人, I want OpenAI 加急档（fast）按标准价的 2 倍估算、gpt-5.5 按 2.5 倍, so that 估算成本与 pi 1.0 一致，不再按标准价低估。
9. As a 计费负责人, I want Anthropic 流在后续增量中报告的 1 小时缓存写入也被计入, so that 经网关转发时 1 小时缓存写入不会按 5 分钟费率估价。
10. As a 宿主开发者, I want 自带目录中型号的默认 samplingParams 在 full 入口和 simple 入口都只合并一次, so that 两种入口发出的请求一致。
11. As a 宿主开发者, I want 调用级的 samplingParams 覆盖型号默认值，且二者都不能覆盖 model、tools、store 等保留字段, so that 默认参数不会扩大请求的权限。
12. As a Agent 开发者, I want Responses 流中参数未接收完成的工具调用被识别为协议错误, so that 我不会执行一个参数被截断或串混的工具调用。
13. As a Agent 开发者, I want 即使厂商发送了缺失或重复的输出索引，被覆盖的旧工具调用块也会被检查, so that 不合规的服务端不能绕过这项检查。
14. As a barness 模块开发者, I want 用 GenerateImages 入口生成或编辑图像, so that 不必为图像伪造聊天历史或解析聊天消息。
15. As a barness 模块开发者, I want 用 Classify 入口一次提交一组分类问题并拿到类型化的答案, so that 业务判断可以直接读取概率和选项。
16. As a 云端宿主开发者, I want 每份 Binding 固定一种模型操作, so that 一个为聊天授权的绑定不会因为目录新增了图像或分类型号而被隐式扩大授权。
17. As a 已有宿主的维护者, I want 不设置模型操作的旧 Binding 继续只表示聊天, so that 升级后现有聊天调用无需改配置。
18. As a 宿主开发者, I want 拼错或未知的模型操作值在发请求前被拒绝, so that 配置错误不会静默落成聊天调用。
19. As a 宿主开发者, I want 用聊天绑定调用图像或分类入口时在读取凭据之前就被拒绝, so that 错用绑定不会触达厂商，也不会读取不相关的凭据。

## Implementation Decisions

### 基线迁移

- 冻结 oracle 整体换为 npm `@earendil-works/pi-ai@1.0.0`（tag `v1.0.0`，commit `a13d35a742c6ef8462812a28fbe1d8c8b7431c32`），不并行保留 0.87.1。按 ADR-0004 的步骤重做等价核验，更新 provenance 与分类账，之后删除 0.87.1 副本。
- oracle runner 适配 1.0 的入口变化：聊天入口在运行时拒绝非聊天型号，聊天型号列表只返回聊天类型，旧的图像集合导出已删除。
- 内建目录与 pi 1.0 模型数据重新逐字段比对；价格与型号差异按 ADR-0018 的包含准则处理，目录升版本。
- 基线迁移单独合入、单独通过门禁，是所有后续工作的前提。

### 随基线迁移的五项聊天行为

这五项在 0.87.1 下是有意的对齐行为，迁移后改为 pi 1.0 行为：

- **无法解析的 Retry-After**：只接受有限的延迟；否则回退为带抖动的指数退避，基数 0.5 秒、上限 8 秒、抖动 0–25%，仍受 Binding 的延迟上限与调用截止时间约束。`retry-after-ms` 同样改为有限性判断。
- **Responses 服务等级计价**：照 pi 逐位移植，flex 为 0.5 倍，priority 与 fast 为 2 倍，gpt-5.5 为 2.5 倍；等级取响应报告值，缺失时取调用选项。从目录读取倍率不在本次范围。
- **Anthropic 1 小时缓存写入**：后续增量中出现该明细时覆盖已有值，不累加；完整性规则不变，该明细缺失仍读作没有。
- **型号默认 samplingParams**：Responses 与 Chat Completions 在构建请求时合并一次，顺序为命名字段、型号默认值、调用级值，后者优先；full 与 simple 入口一致。校验合并后的最终结果不能覆盖保留字段。Anthropic 与 Gemini 没有该字段，不变。
- **Responses 未完成工具调用**：停止原因为工具调用时逐个工具块检查是否收到对应的完成事件，未完成即为协议错误；被重复输出索引覆盖的旧块同样检查；现有终态事件检查保留在前。

### 模型操作与目录

- 新增模型操作类型，取值 chat、image、classifier。
- 现有 `Model` 的字段与含义不变，仍表示聊天型号；新增 `ImageModel` 与 `ClassifierModel`。三者各自声明 Provider、协议、ID、名称，不嵌入公共结构，因为把 `Model` 的字段改为嵌入结构的提升字段会使宿主的 keyed struct literal 编译失败。
- 型号身份为（操作、Provider、协议、型号 ID），保留协议维度；同一 ID 可在不同操作下各出现一次。
- `ImageModel` 携带输入/输出模态、能力（参考图数量、输出数量、尺寸或分辨率、mask、透明背景）与按模态的费率。`ClassifierModel` 携带上下文窗口、能力（支持的问题类型、单选选项上限、评分级数范围）与费率。
- 目录分别持有三类型号，聊天列表与查找只返回聊天型号；新增图像与分类的强类型查找与列表。
- 目录构造时拒绝重复完整键、操作与模态或能力矛盾、非负有限之外的价格，以及型号声明的模态缺少费率；深复制覆盖新增的切片、map 与能力结构；版本与哈希覆盖三类型号，canonical 输入扩展时升版本并重建发布快照。
- 现有目录文件已接近 500 行，先按模型类型、内建数据、索引与校验拆分，再加入新类型。

### Binding 与授权

- Binding 新增模型操作字段。一份 Binding 固定一个 Provider、协议和操作；型号白名单在这三个维度下解释；Target 仍为绑定 ID 加型号 ID。
- 操作字段的零值规范化为 chat。这是对 Binding 失败关闭零值约定的有意例外：Binding 由宿主产出，属于对外契约；旧绑定只可能表示聊天，零值为 chat 不放大任何授权。该例外写入字段说明与公共契约文档。
- 非空的未知操作值与不支持的认证方式一样，以 `invalid_request` 在 binding 阶段失败，不发请求。
- 入口决定期望的操作：Stream/Complete 为 chat，GenerateImages 为 image，Classify 为 classifier。预检先核对绑定的操作，再读对应类型的目录并求白名单交集，最后解析凭据。操作不匹配返回 `tenant_denied`，在 capability 阶段失败，不读凭据也不发请求。
- 多个绑定可共享凭据引用与账户作用域；凭据解析仍按本次绑定的版本做一致性核对。
- 调用归属新增操作字段，调用开始时即由入口填写；Provider、协议、型号与账户仍在快照一致后才填写。

### 调用管线与 adapter

- 从现有调用执行流程中抽取私有的调用运行时，负责 deadline、作用域、绑定、目录授权、凭据快照、元数据、请求头、尝试、准入与终态观测。聊天专有的历史、SimpleOptions、原生状态封套、assembler 与事件队列留在聊天路径，不为 unary 调用构造空历史。抽取有聊天与 unary 两个真实调用方。
- adapter 注册表改为按（操作、协议）分派。现有 adapter 接口保持聊天专用；新增图像与分类两份私有 adapter 契约，接收共同的已解析调用上下文。
- 新增协议标识 `openai-images`、`google-interactions`、`typesafe-system-one`，新增 Provider 标识 `typesafe`。
- 新的图像与分类选项实现现有的 Options 接口，使"选项与绑定协议不匹配"的检查对新操作同样生效。
- 终态观测改为读取与操作无关的终态摘要，不再依赖聊天消息。
- unary 路线复用 Gemini adapter 已在使用的直连设施：共享 HTTP 客户端与传输时限、非 2xx 分类、厂商请求 ID 读取、初始请求的发送、用量记录与许可释放。不引入 SDK 中间件。
- 首期不开放动态注册，注册表在构造时固定。

### 公共入口与失败契约

- Client 与 HookedClient 新增 GenerateImages 与 Classify。两者同步返回最终结果，支持 context 取消，不产生 delta 事件，不接受 SimpleOptions；选项为 nil 表示协议默认。
- 结果共同包含停止原因、错误消息、调用元数据与用量；厂商确实报告时才填写响应 ID 与实际作答型号。成功为 stop，失败为 error 或 aborted，并返回 `*ai.Error`。
- 新增 Phase `response`，表达 unary 响应体的读取、解码与校验失败。这是公共契约的加法变更，同步更新错误分类文档与词汇表。HTTP 状态分类沿用现有规则：401/403 为 upstream_auth，429 为 rate_limited，5xx/408/409 为 upstream_error，其他 4xx 为 invalid_request。

### 重试、准入与资源

- 请求回调每次逻辑调用只执行一次，重试复用回调后冻结的请求；每次尝试有独立的 AttemptID 与准入许可。许可持有到响应读完并解析结束，任何失败都释放。
- 初始请求重试只由 Binding 决定，默认不重试。成功响应之后的 EOF、坏 JSON、坏 base64、缺图、缺答、概率错误一律不重放；资源超限与取消不重试。
- 新增按总字节计量的 unary 响应读取器，由现有的错误体读取器参数化而来；聊天响应读取保持原样，unary 成功响应按总输出上限计量，非 2xx 仍按错误体上限。
- 资源策略新增可选的图像与分类子策略，未配置即禁用对应操作；启用时所有容量必须为正且有限。子策略在 Client 构造时深复制。

| 策略 | 限制 |
| --- | --- |
| 已有全局策略 | 请求字节、输出字节、调用/连接/响应头/读空闲时限、并发；三种操作共同遵守 |
| 已有单图上限 | 改为同时覆盖参考图与 mask |
| 图像子策略 | 输入图片数量、输出图片数量、单张输出字节、输出总字节 |
| 分类子策略 | 问题数量、状态字节、单个问题字节；回调后再次检查 |

- 实际生效值取宿主策略与该协议或型号硬限制的较小者。输入先按已知长度检查再复制；base64 免解码估算尺寸；MIME 复用现有图像类型校验；不同时常驻 base64、解码字节和多份响应体。不读任意文件，不下载 URL。

### 图像：共同契约

- 请求为提示加有序参考图，参考图复用现有图像类型。这是对 pi 有序混合输入的有意收敛：对 OpenAI 编辑无损，对 Google 丢失文本与图片交错，作为扩展登记；出现真实需要时再扩展。
- 结果为有序的文本与图片块，是独立的封闭类型，不给现有图像类型加 assistant 内容标记。输出整体校验通过后才发布；失败时输出为空，用量与元数据保留。
- 厂商拒绝或阻断为 upstream_error；200 完成却没有有效图片为 protocol，在 response 阶段失败。
- 每种选项只属于一个协议，不设通用选项袋，不自动并发凑数量；不支持的选项在发请求前拒绝。

### 图像：OpenAI Images

- 绑定为 OpenAI × `openai-images` × image，Bearer 凭据。无参考图走生成端点，有参考图走编辑端点。
- 直连 HTTP，适用"SDK 确实无法满足时仅对受影响 Provider×协议直连"的例外条款：已安装的 openai-go 以 io.Reader 加 multipart 表示编辑图片，并在应用请求选项前把整个表单编码进无界缓冲区，无法在读入前限制大小；2026-10-02 的 v3.71.1 新增了流式编码方法，但默认请求路径仍先缓冲，也没有 JSON 编辑路径。聊天 SDK 路线不变。
- 编辑使用 JSON 请求体，参考图与 mask 为内联 data URL；file_id 与远程 URL 在构造时和回调后都拒绝。官方参考文档化了 JSON 请求体，但官方示例全部是 multipart；因此 JSON 编辑是 OpenAI 路线的第一个真实冒烟检查点，通过前编辑能力不进支持目录，运行时不切换到 multipart。
- 硬限制：每个内联图 URL 不超过 20971520 字符；GPT image 型号最多 16 张参考图；mask 与第一张参考图同尺寸；数量 1–10；提示 1–32000 字符；透明背景要求 png 或 webp。
- 选项为数量、尺寸、质量、背景、输出格式、输出压缩、mask、输入保真度、审核级别，按型号校验，例如输入保真度在 gpt-image-2 必须省略。不暴露流式、partial images、响应格式与 user 字段。
- 响应映射全部图片条目，按最终请求的输出格式与实际内容设置 MIME，严格校验 base64。响应没有响应 ID 与型号字段，二者不设置；`x-request-id` 记为厂商请求 ID。不保留 revised prompt，官方说明 GPT image 型号不返回它。
- usage 按存在与否处理：缺失为未上报，缺输出分项为部分上报。
- 首批型号为 `gpt-image-2.5-sunburst-2026-09-08`（编辑端点的默认型号的日期快照），固定快照 ID 以便证据可复现；其他型号按 ADR-0018 逐个评估。

### 图像：Google Gemini Interactions

- 绑定为 Google × `google-interactions` × image，`x-goog-api-key` 凭据，端点 v1beta 的 interactions。现有 generateContent 聊天 adapter 不迁移，ADR-0012 把图像输出型号排除在聊天目录外的决定继续有效。
- 选 Interactions 而非扩展 generateContent：官方称 Interactions 推荐用于所有新项目，新型号与多模态能力只在它上面发布，generateContent 被列为 legacy 但继续支持；Interactions 提供类型化的图像输出配置与显式模态用量。代价是默认服务端存储、需要拒绝的字段更多，且其 schema 在 2026 年 5–6 月刚发生过破坏性变更。
- 固定 v1beta：v1 参考的型号枚举不含当前图像型号，并要求带前缀的型号名。不做版本自动回退。
- 固定无状态同步调用与内联返回。工单 14 的真实服务拒绝显式 `delivery: inline`，维护者于 2026-10-08 批准请求省略可选 delivery；回调禁止添加任何 delivery 字段，响应仍须内联且无 URI/续读（ADR-0023）。回调后拒绝续接 ID、后台执行、Agent、工具、环境、回调地址、续读令牌、服务等级、流式字段，以及网址形式的输入内容和输出交付方式。
- 硬限制：内联请求总大小 20 MB；参考图最多 14 张，首批型号为最多 10 个物体加 4 个角色；首批型号支持 1K、2K、4K。官方说明输出图片数量不一定精确，因此不承诺精确数量。
- 选项首期为宽高比与图像尺寸，按型号校验；不模拟 OpenAI 的 mask。
- 只接受 completed 状态；failed 与 cancelled 为 upstream_error；in_progress、requires_action 以及带续读令牌的响应为 protocol。遍历全部模型输出步骤的内容并保留顺序；响应 ID 仅用于诊断，不转为可续接状态。
- 首批型号为 `gemini-nano-banana-2.1`。`gemini-3.1-flash-image` 已于 2026-10-06 弃用，`gemini-2.5-flash-image` 已弃用且官方关闭日期自相矛盾，Imagen 4 已关闭，均不列入。

### 图像回调边界

- 两条图像路线沿用请求头、请求体与响应三种可信回调，回调信息增加操作字段。回调后重新核对型号、内联图片、大小、允许字段与 Google 的固定项；结果 MIME、输出配置与计价以冻结后的最终请求为准。回调可在允许范围内修改输出格式等字段，不能改变端点、操作或授权型号。无效回调为 callback_failed，扩大授权为 tenant_denied。
- unary 路线在取得成功响应后调用一次响应回调，再读取响应体；Gemini 聊天路线仍不调用响应回调。

### 分类：TypeSafe System One

- 绑定为 TypeSafe × `typesafe-system-one` × classifier，Bearer 凭据，直连 HTTP。TypeSafe 只有官方 Python 与 JS SDK，没有 Go SDK；pi 同样直连。
- 请求为状态与问题集合。状态与问题说明可为 JSON 字符串、对象或数组；单选的选项说明可为 null；JSON 数字保留精度。这比 pi 宽：pi 的状态只接受对象，说明只接受字符串，选项说明只接受字符串。
- 问题为封闭的三种类型：单选（选项到说明的映射）、评分（有序等级说明）、是非（真与假的说明）。是非问题在线上编码为 noul。
- 答案：单选为选项、完整分布与置信度；评分为期望值、置信度，以及可选的等级分布与图例；是非为"是"的概率。pi 丢弃评分的分布与图例，barness 保留。
- 响应中的型号是实际作答的版本化 ID，记为响应型号，不覆盖授权的型号 ID；`x-typesafe-request-id` 记为厂商请求 ID。
- 选项首期为空类型。不暴露 temperature 等参数；pi 暴露了 temperature，但 System One 会忽略它。
- 能力校验：单选最多 255 个选项，评分 2–10 级，以官方文字说明为准；官方 OpenAPI 比文字宽松，这些规则只属于本 adapter。上下文为每请求 64k token，状态加最长问题合计 32k token；barness 不在本地计 token，按字节限制兜底，超限由厂商返回 422。
- 回调后重新解码并冻结最终问题集合，重新执行全部校验；答案按最终集合校验。先登记用量再整体校验答案：每个问题都有类型匹配的答案，不许多出问题；概率与置信度有限且在 0 到 1 之间；分布之和在容差内接近 1；单选是最高概率项之一；评分在等级范围内并与分布一致。不合格为 protocol，在 response 阶段失败，答案为空、用量保留，不重新归一化。
- 一次 Classify 发一份问题集合，不在客户端拆分并发。置信阈值、转人工与业务路由属于宿主。
- 重试由 Binding 决定，默认不重试；官方 SDK 与 pi 默认重试两次，作为配置位置的差异，不作为行为差异登记。
- 首批型号固定为 `jev-1.13.0`，首期不列入 `jev-latest` 与 `jev-preview` 别名，因为官方说明别名会随新版本移动。

### 用量、计价与观测

- 三种操作共用现有 Usage 与每次尝试的上报完整性状态，不新增平行的图像用量结构或第二个上报状态。另设一套平行结构，会让通用汇总把"未上报加零值"误读为没有消耗；而 ADR-0010 已规定零值不表示免费、部分上报表示缺失项按零计。pi 自己也用聊天的用量结构表示图像用量。
- Usage 新增可选的模态分项：输入文本、输入图片、输出文本、输出图片的 token 数，均区分未报告与零。聊天不设置该字段，序列化不变，pi 差分投影不受影响。
- 各协议映射：

| 协议 | 输入 / 输出 / 推理 / 总量 | 模态分项 | 完整上报的条件 |
| --- | --- | --- | --- |
| OpenAI Images | 输入 token / 输出 token / 不设置 / 厂商总量 | 输入与输出明细中的文本与图片 | 输入、输出、总量与输入明细齐全；缺输出明细为部分上报 |
| Google Interactions | 总输入 / 总输出加思考 / 思考 / 厂商总量 | 按模态的输入与输出 | 四个总量与两组模态明细齐全 |
| TypeSafe | 输入 token / 输出 token / 不设置 / 二者之和 | 不设置 | 两个计数都存在 |

- Google 的思考 token 不含在总输出里（官方示例 7、20、22、49），加入输出后保持"推理已包含在输出内"的现有定义。总量字段的说明修正为"厂商报告了总量时取厂商值，否则为分项之和"。
- 图像费率按型号分模态存放：输入文本、输入图片、输出文本、输出图片，以及可选的缓存读取费率。目录校验保证型号声明的每个模态都有费率，所以完整上报一定能算出费用；缺分项时只按已知分项估价并为部分上报。OpenAI 的缓存输入价不适用于直接调用 Images API，不设缓存费率。官方"每张图约多少钱"只是派生值，不叠加计价。分辨率与 token 的对应因型号而异，只作为能力说明，计价只依据厂商报告的 token。费率录入时带来源与抓取日期。
- TypeSafe 按官方价只对输入计价，输出费率为零。pi 把直连 Jev 全部定价为零，作为扩展登记。
- Observer 记录增加操作字段，模态分项进入 Observer 与审计白名单；仍不含提示、base64、分类状态、答案或错误正文。

### 支持矩阵

- 支持矩阵现以组合名为键并校验 Provider 与协议一致。新增三个组合：OpenAI 图像、Google Interactions 图像、TypeSafe 分类；矩阵行增加操作字段并纳入一致性校验。六个聊天组合不变；共享 adapter 或同 Provider 聊天组合的通过不传播到新组合。

### 需要新增与修订的 ADR

- 新增"多类型模型操作与 Binding 授权"：操作维度、四维型号身份、零值例外、按（操作、协议）分派、response 阶段。
- 新增"原生图像与 TypeSafe unary 协议"：直连 HTTP 的例外理由、Interactions 与 generateContent 的取舍、v1beta 固定、单一用量轴与按模态计价。
- 修订 ADR-0001（单次生成轮次扩展为单次模型操作）、ADR-0002/0007/0008（unary 读取器、子策略深复制、许可持有到解析结束）、ADR-0004（基线换为 1.0.0）、ADR-0005/0009（新路线的拒绝字段、操作元数据、unary 响应回调时机）、ADR-0006（无法解析的 Retry-After 改为退避）、ADR-0010 决策五（增加 fast）与用量部分、ADR-0011 决策三（增量中的 1 小时明细覆盖更新）、ADR-0012（新图像路线与聊天路线并存）、ADR-0014（扩展路线增加两条图像路线）、ADR-0016/0017（新组合、操作字段、live 预算、门禁输入）、ADR-0018（非聊天型号的包含准则与豁免）。
- 同步更新公共契约（入口、Phase 列表、零值规则）、差异登记（基线版本与扩展）与交付说明中的支持矩阵。

### 词汇表

ADR 接受时同步写入：

- **模型操作（Operation）**：一次逻辑调用要求模型完成的工作类型，取 chat、image、classifier 之一；由调用入口决定，由 Binding 固定。
- **图像型号（ImageModel）** 与 **分类型号（ClassifierModel）**：目录中按操作区分的型号元数据；同一 ID 可在不同操作下各出现一次。
- **unary 调用**：一次请求得到一份完整响应、不产生流事件的逻辑调用；image 与 classifier 都是 unary 调用。
- 修订 **barness-ai**：每次调用处理一次模型操作。
- 修订 **Support Matrix**：以组合为行，每个组合是一个操作 × Provider × 协议。

## Testing Decisions

- **好的测试只验证外部行为。** 测试经公共 Client 入口发起调用，断言宿主可见的结果：发出的请求、返回的结果与错误分类、调用元数据与尝试记录、Observer 记录、资源探针读数。不断言内部函数、结构体字段或调用顺序。
- **不新增测试接缝。** 沿用仓库已有的最高接缝：离线 E2E 以公共 Client 对本地受控 Provider 替身与宿主替身运行；同一批场景经 pi 差分 oracle 比较请求与结果；每个组合由真实冒烟产出支持矩阵证据；发布门禁读取全部证据。唯一的扩展是在现有场景 fixture runner 中增加返回整份 JSON 响应的 unary 场景类型；受控 Provider 替身已经能返回任意 JSON 响应体。
- **先列失败方式，再写实现。** 每个工作包实施前先写出下表对应组的失败场景 fixture，再写代码。

| 验证组 | 必须覆盖的行为 |
| --- | --- |
| 基线迁移 | 新 oracle 等价核验与哈希校验；runner 拒绝版本或数据哈希不符的副本；全量差分 0 pending；内建目录与 1.0 数据逐字段一致或已登记 |
| 聊天五项 | 无法解析的 Retry-After 退避且受截止时间约束；fast ×2、gpt-5.5 ×2.5；1 小时明细在增量中覆盖不累加；samplingParams 在两种入口合并一次且不能覆盖保留字段；缺失或重复输出索引覆盖的旧工具块仍被检查 |
| 身份与授权 | 同一 Client 混合三种操作；跨租户同名绑定；零值绑定调用新操作被拒；未知操作被拒；同型号 ID 跨操作不越权；选项与协议不匹配；凭据轮换冲突；不跨 key 或端点回退 |
| 生命周期 | 取消、响应头/读空闲/总超时、准入拒绝；200 后读断不重放；所有失败关闭响应体并释放许可；请求回调只执行一次；尝试归属正确 |
| 资源 | 大于帧上限、小于输出上限的 JSON 成功；整体超限及时失败；输入与输出图片的数量、单张、总量超限；base64 膨胀；回调插入大图；构造后修改原配置的子策略不影响 Client |
| OpenAI 图像 | 生成与编辑的路径和认证；JSON 参考图与 mask；内联 URL 上限；file_id 与远程 URL 被拒；全部图片条目；输出 MIME；输入保真度按型号校验；无图、坏图、拒绝；usage 缺失与缺分项 |
| Google 图像 | v1beta 与裸型号 ID；无状态与内联交付不可放宽；网址形式的输入与输出被拒；其余拒绝字段；20 MB 上限；全部模型输出步骤；五种状态与续读令牌；思考 token 映射满足总量等式 |
| TypeSafe | 三种问题混合；是非与 noul；有序评分；缺答、多答、错型；选项键、概率范围与总和容差；版本化响应型号；401/403/422/429/529；答案错误但用量保留；回调改问题后按最终集合校验；回调插入超限问题被拒 |
| 回调与观测 | 改型号、凭据、目标、URL 或 file_id、存储或续接被拒；格式按最终请求解析；响应回调只看元数据；Gemini 聊天仍不调用响应回调；Observer 不含提示、base64、状态或答案；异步拥塞不改变结果；模态分项进入审计白名单 |

- **差分与扩展登记。** 聊天五项与 TypeSafe 的请求编码和基本答案转换进入 1.0 差分；TypeSafe 差分只覆盖 pi 能表达的输入子集，不比较费用。更宽的输入形状、评分分布与图例、严格答案校验、版本化型号 ID 与目录价格逐项登记为扩展。两条原生图像路线照 DeepSeek × Responses 的先例登记为扩展接入路径：fixture 全部跳过差分，并有离线用例断言它们已登记。目录包含测试为原生图像型号增加显式豁免，Jev 只比较 pi 拥有的字段。
- **追溯与真实冒烟。** 三条新路线分配新的场景 ID 前缀，进入发布追溯表的场景、P0、差分扩展路线与 live 组合列表。live 预算按操作单独设定：图像按张数与分辨率，分类按问题数。首批真实冒烟的重点是 OpenAI JSON 编辑是否被接受，Google v1beta 下首批型号的输出配置、终态与 usage 形状，以及 TypeSafe 首批型号与错误体形状。
- **可重复产物。** 每次 E2E 运行产出证据包，带 SDK 与目录版本并经脱敏审计；live 只经支持矩阵合并命令写入矩阵；发布门禁写出目录快照。图像 live 只验证可读图片、格式、尺寸与数量约束和协议结果，不做像素相等断言。分类的协议测试使用合成的确定响应；中文业务效果另用固定标注集评估准确率、误判与校准。
- **已有先例。** 场景 fixture 与差分用例沿用各协议现有 fixture 的结构；扩展路线登记沿用 DeepSeek × Responses；回调守卫、托管工具放行、字节限额、准入压力、资源释放、观测脱敏都有对应的现有 E2E 组可供照搬；重试时序使用现有的可替换时钟，资源读数使用现有探针。
- **发布门禁。** 现有 vet、race 与离线 E2E 不退化；新 oracle 账本 0 pending；三个新组合的真实冒烟、脱敏审计、目录与价格快照、追溯完整、图像设计负载下的内存与并发压力证据齐备。未运行的新路线记为 NOT_RUN；必须交付的能力不能标为不支持来通过门禁，mask 等可选能力可按型号标为不支持。

- 经 OpenRouter 或任何网关的图像路线；经 OpenRouter、Cloudflare、Vercel、OpenCode 的 Jev 分类路线。

- 模型托管、自动回退到其他 Provider、协议或 key。

## Further Notes

- **实施顺序**：基线迁移 → 聊天五项 → 类型与授权 → 共同运行时与资源计价 → 验收设施 → TypeSafe → OpenAI 图像 → Google 图像 → 发布证据。基线迁移先行，否则聊天五项无法通过门禁。TypeSafe 先于图像，用较小的 JSON 负载验证 unary 运行时。OpenAI 先于 Google，因为 Google 的协议与型号波动最大。两条图像路线都必须交付，Google 不能长期停留在接口占位。
- **时效风险**：厂商事实取自 2026-10-07 的官方页面。Google 的首批型号在原设计完成次日即发生更替，Interactions schema 也刚发生过破坏性变更。实施时把采用的请求与响应形状、型号能力与价格存为带来源与抓取日期的 fixture，真实能力以各组合自己的冒烟证据为准。
- **证据来源**：底稿、评审与三份核验记录已合并进[实施设计](design.md)，每条关键事实都在其中直接引用一手来源。pi 事实以 tag `v1.0.0` 的源码为准，引用为 GitHub 永久链接；本仓库事实以 `fdb075b` 为准；厂商事实以官方页面 2026-10-07 的状态为准，引用为官方 URL。实施设计第 16 节列出仍待真实冒烟确认的事项。
- **升级与回退**：旧聊天入口、Target、Model 字段与聊天目录含义不变。新操作经独立绑定、目录条目与子策略显式启用；回退时禁用对应绑定，不落到聊天 adapter。每条新路线可独立停用；停止路由不保证已发出的请求没有产生费用，用量按尝试留档。持久化的旧聊天数据按聊天解释，不批量改写。
- 本规范没有运行真实冒烟，也没有读取真实凭据。

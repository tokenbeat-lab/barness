# 09: 验证共享 Client 的隔离、回调授权与资源释放

Status: claimed
Type: task

由 2026-10-17 implement-spec 实施指令发布。

**What to build:** 本地与云端 Host 共享 Client 并发使用三种 GLM 协议时，租户、账户、原生状态和缓存互不串用；回调不能越权，取消和限额会及时释放资源。

Blocked by: 03, 05, 07, 08

依据：GLM 接入 spec R02、R15、R16、R19；验收组 A11、A12、A13；User Stories 11、12、32、33、34、40、41、42、46、47、50。

- [ ] 先写跨租户/账户/协议的真实工具历史、并发取消、回调越权与资源超限 E2E，再做必要修复；使用已确认的公共 Client 接缝。
- [ ] 相同 BindingID、ModelID、session 名而不同租户/账户不会串用凭据、缓存 key 或 Native State；RequestID 仍由 Host 保证全局唯一。
- [ ] trusted、持久化重新担保、未担保、跨账户和跨 API 状态按合同回放/降级；授权跨模型转换保留可见内容和有效工具配对，最终不留未授权引用。
- [ ] header→payload→response 顺序保持；模型/Key/目标/托管工具/原生引用授权和型号硬约束都检查最终请求，具名选项、sampling 与 OnPayload 均不可绕过。
- [ ] 发送前拒绝零请求/零 Attempt；OnResponse 等发送后失败保留实际 Attempt/已知用量；重试固定原配置和合法回调字节。
- [ ] Admission、首帧前后取消、调用/请求时限、body/帧/输出/队列上限都经过现有策略；最终结果只结算一次，body/goroutine/许可释放可观察。
- [ ] 请求/目录/选项/返回 map 与原始 JSON 的复制边界可验证；合法调用后修改不影响运行中或另一租户结果，不承诺调用方并发写正在读取的 Go map。
- [ ] Observer 只保留元数据，错误与证据不泄露 Key、提示、思考、工具参数或原生状态；每个证据包通过脱敏审计。
- [ ] 产出可重放隔离证据、race/资源结果和设计负载记录；保留已有 Provider 的共享生命周期语义。

**独立验收：** 同一 Client 并发完成三个协议的工具调用与取消/限额故障，按租户账户核验所有结果、重试快照与资源回收。

**依赖理由：** 跨协议真实历史、回调和重试快照需要 03/05/07 的完整往返及 08 的错误重试行为。

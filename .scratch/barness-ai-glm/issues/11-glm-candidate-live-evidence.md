# 11: 取得六个候选型号组合的真实 API 与价格证据

Status: ready-for-agent
Type: task

由 2026-10-17 implement-spec 实施指令发布。

**What to build:** 维护者通过公共 Client，在三种 GLM 官方协议上分别验证 GLM-5.3 和 GLM-5.2 的必交能力，并获得可追溯的容量、用量和美元价格候选快照。

Blocked by: 09

依据：GLM 接入 spec R03、R06、R07、R13、R14、R17、R21；验收组 A02、A09、A15；User Stories 13、14、38、39、54、55、56。

- [ ] 先登记每协议两型号的必交能力、未知变量、预期、预算和证据格式，再扩展现有候选 live 验收；正式支持仍由公共 Client 证明。
- [ ] 核验中国区标准 Key 和三条官方端点；每进程仅本组合 Key，显式 SDK 配置和双开关生效，账户/区域/Key 类别用别名记录，不读取套餐或其他环境凭据。
- [ ] 为六个候选身份固定有日期的来源和容量上限；1M/128K 不冒称未经核验的精确整数，需要保守值时明确其 barness 支持子集性质。
- [ ] 从官方人民币报价取得两型号的输入/输出/缓存/阶梯费率，并以有来源、日期、固定换算率转成美元候选 Price Snapshot；无来源的零价格不能作为免费。
- [ ] 逐协议完成两型号的文本、工具往返、合法历史、可用思考、取消/用量等必交场景，专项收敛 Responses effort、Chat temperature=0/include_usage、Messages thinking/签名与默认头的未知事实。
- [ ] 遵守每组合每次运行最多 24 Logical Call/32 HTTP Attempt、每次最多 4096 输出 token、进程 1800 秒/调用不超 120 秒及更短 Host 时限；Binding/SDK 重试关闭，场景级故障重试至多一次且计入预算。
- [ ] 先预留预算，一次只改一个待确认变量；缺 Key 为 NOT_RUN、真实失败为 FAIL，已发生失败保留，不隐式加预算或主动制造欠费/套餐故障。
- [ ] 返回六个候选的实际结果、用量/估算、SDK、request id 来源、截断标记及脱敏审计；候选报告不更新正式支持矩阵。
- [ ] 任何必交型号/协议失败都阻止候选整体验收，不删目标或把必交能力改成 UNSUPPORTED；可选可观察思考的限制只按 spec 的证据条件登记。

**独立验收：** 获得三协议、两型号各自完整的候选报告和有来源的容量/价格快照；若缺凭据或能力失败，结果如实保留而不宣称交付。

**依赖理由：** 付费候选验收必须建立在三路线完整行为、故障和隔离/资源检查之上；可与 10 的固定基线核验独立推进。

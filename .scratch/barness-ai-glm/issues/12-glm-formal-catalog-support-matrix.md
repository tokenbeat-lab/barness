# 12: 发布六个正式目录条目与三个独立支持记录

Status: ready-for-agent

**What to build:** Host 能从内置 Catalog 查询两型号各自的三协议身份与正确美元价格；支持矩阵只显示这三条 GLM 路线在正式目录快照下取得的自身证据。

Blocked by: 10, 11

依据：GLM 接入 spec R06、R17、R20、R21；验收组 A09、A14、A15；User Stories 15、16、38、39、54、55、59。

- [ ] 先写公共 Catalog 查询、内容哈希、独立模型身份与矩阵拒绝错误报告的失败用例，再将 11 的已确认候选数据纳入正式目录。
- [ ] 六个 text-only 条目分别保存，不从 Chat 字面量派生其他协议；各自的档位、硬约束、模态、容量、费率和来源可追溯。
- [ ] 目录内容变化更新 Version/Hash 及正式价格快照；公开查询返回独立副本，一条协议/型号的修改不能影响其他条目。
- [ ] 美元价格估算保留币种契约、固定换算依据、缓存/上下文阶梯和 Reasoning 属于 Output 的语义；不得称为厂商实际账单。
- [ ] 为 zhipu-chat/zhipu-responses/zhipu-messages 定义独立正式报告，场景内逐型号可追溯；只允许自己的完整当前 Catalog Hash 报告更新自己的矩阵行。
- [ ] 同票更新正式路线注册、报告/矩阵校验及发布门禁的十三组合结构与必交集合，先覆盖缺/错路线、缺型号和错误 UNSUPPORTED 的负例；不能让新增矩阵行与仍只认识十组合的校验器并存。原十组合合同保留，完整发布证据在 13 收敛。
- [ ] 在正式内置目录 Hash 下重新执行三组合、两型号必交 live 场景并留完整脱敏证据；候选通过、旧 Hash 或原厂报告不能替代。
- [ ] 缺 Key、窄化/旧/错误 Provider/API/型号报告、缺必交能力、伪造 UNSUPPORTED 和环境失败不能置完整通过；保留失败与最近有效通过事实。
- [ ] 依 10 的路由判定核验正式目录来源和适用差分/扩展记录；矩阵与查询的公开行为可重复验证。
- [ ] 本票只发布新三组合的自身正式支持记录；其余十组合因目录快照变化需要的当前发布复验在 13 完成，不伪造为已经重新通过。

**独立验收：** 查询内置六条独立模型数据，合并三个同 Hash 的正式 GLM 报告；错误来源报告被拒绝且不修改其他支持记录。

**依赖理由：** 需 10 明确基线/扩展和目录比较规则，以及 11 已通过的六组合事实与价格/容量来源，才能正式纳入。

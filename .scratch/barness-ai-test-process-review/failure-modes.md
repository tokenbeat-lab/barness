# 第 1 节失败方式与公共接缝

用户已经按 plan.md §1.2 确认接缝；先建立进程失败场景，再逐片实现。测试不得执行实际 race、压力或付费 live。合成回执里的阶段名称不代表执行该阶段。

1. run.py：普通父子进程继承重负载/凭据环境；重复覆盖；非零退出/启动失败/取消/超时错误写成 PASS；来源变化；没有测试/缺主 manifest/多个匹配包/错 package/篡改 artifact/audit 缺失或有发现；不安全 slug/路径；输出原始秘密；子进程未释放。
2. releasegate：旧入口仍执行验证；索引/阶段缺失、未知字段或重复 JSON 字段、任意 PASS、空测试、错误退出/命令/人工选择、NA 缺理由或与影响范围冲突、来源/选定输入漂移、路线错配、manifest/audit/artifact 损坏、原生消费缺失、缺少阶段即放行；重复输出目录覆盖。
3. cleanup.py：相对/绝对/编码路径解析错误、同名日志混淆、占位符/尾部标点误判、既有缺失混入新增、索引依赖遗漏、输入扫描截断、未知状态误当成功；父子重叠移动、批次/哈希错误、锁冲突、symlink/路径穿越、源目标冲突/移动中断；restore 覆盖不同原件；未满七天/新引用/元数据缺失/校验失败仍删除；删除中错误补记成功。
4. 旧实际入口：普通 E2E 和 release 包自行启动设计负载；GLM/Multimodal 设计负载未 opt-in；差分调用/冻结安装仍有活动引用；新 CLI 继续要求旧十门禁输入。先用定向普通进程验证，不运行旧完整链。

每次 RED/GREEN 的真实数字退出与原件指针追加 execution-log.md。维护工具自测在临时合成仓库运行，保留过程回执索引；不把真实 .evidence 作为破坏性夹具。

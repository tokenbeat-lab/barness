# xAI formal producer/consumer wire contract

Accepted preparation boundary: [ADR-0054](../../docs/adr/0054-barness-ai-xai-responses.md) and [plan](formal-qualification-plan.md). This document coordinates two independent implementation owners; it is not a new live authorization.

- Exact new native entry: `^TestXAIFormal$`, existing route/key/proxy/permissions environment forwarding. Stage is selected by this exact entry; no automatic upgrade from candidate grant. Candidate entry and originals remain candidate-only.
- Own formal sidecar: `xai-formal-report.json`, kind `xai-formal`, stage `formal`, mode `live` or `controlled`. Use existing candidate report machine/scenario/budget JSON fields plus `buildSourceSha256` for the injected frozen source. Formal uses full current Builtin version/hash; candidate retains independent CandidateCatalog.
- Same schema1 grant fields as current xAI grant; formal requires stage=formal and the correct mode. Consumed claim binds its exact hash/source/binary and is durable before requests. Use the same exclusive common-Git grant ledger; no reset/reuse. Expiry is checked at the execution/claim time, not against later qualification time.
- Fixed18scenario IDs and fixed24call mapping: encrypted-continuation/tools-auto/tools-required/tools-parallel/tool-result-image/cache-usage each2; other12each1. Zero automatic retries, per-call visible1024/reserved8192, totals24576/196608, process1800s/call65s/finalization30s, finite positive grant USD stopping threshold. No generic normalized-total-output cap.
- Keep current capture label/files: text/image, first/continued, calls/results, first/repeat as applicable; full http/result/observer triplets and streaming events. Preserve native persistence/continuation proof, full tool pairing and PNG/JPEG order, raw usage presence/arithmetic/cache and independently computed catalog cost.
- A real response x-request-id is adopted by parallel ticket13; missing header stays unreported. Consumer compares recorded header, Result/Attempt and terminal Observer; no invented ID or requirement that service always supplies a header.
- Formal producer additionally writes existing standard `live-report.json` as a projection of the18scenarios. Only live+formal+complete+audited own proof can qualify; candidate/controlled/replay never do. On late finalization failure, invalidate/unpublish any generic formal PASS projection, preserve own non-PASS budget/report and numeric nonzero exit.
- Consumer entry stays `releasegate -live-bundle`. Add supportmatrix `NewXAIReport(dir)` and fixed `XAIExpected()` registry, exact xai-responses identity and release dispatch. Use independent evidence DTOs/validation; producer may keep private report DTO and its own fixed scenario list. Do not create a new CLI flag merely to accept old candidate.
- Native source algorithm remains existing xaiSource: current RegionalExecutionSource file inventory plus independent xAI candidate JSON; this reuse does not grant regional identity. Formal source/build/binary/catalog are all frozen and checked. If a complete formal source-inventory sidecar is needed, name it `xai-execution-source.json` and coordinate its exact JSON shape between owners before coding.
- Native verification derives capability/budget/metadata/capture integrity independently, not from claimed booleans. Fixed Builtin model is global grok-4.7; no provider/endpoint/model fallbacks or UNSUPPORTED escape. Own native manifest branch avoids generic filenames/package/budget assumptions.
- Keep current commit equality at existing new-native-consumer capture boundary. `qualifiedLive` validates content/source/catalog/origin manifest but must not newly require current HEAD; the outer record later compares report commit to actual recorded stage commit. Doc-only closure uses captured schema2 consumer/source-file equality.
- Test first at public CLI/process seams; label controlled/synthetic fixtures honestly. Missing/substituted/duplicate scenes, wrong stage/identity/catalog/SDK/source/binary/grant, missing/truncated/tampered triplets, usage/Observer inconsistencies, expiry-at-claim/reused grant and late I/O/audit failures must refuse. Structural synthetic positive tests are not actual live-stage evidence.
- Final runtime catalog facts/literal stay in ai, without importing internal/testkit/xai into ai. Public catalog E2E reflects deliberately prepared unreleased Builtin wiring and candidate/formal snapshot separation. No main merge/push/publication.

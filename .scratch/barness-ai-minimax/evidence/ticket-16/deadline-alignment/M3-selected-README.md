# MiniMax international candidates

`CandidateCatalog()` decodes the checked-in six independent entries afresh.
`ChatCatalog()`, `ResponsesCatalog()` and `MessagesCatalog()` select their own
declared entries; they do not derive one protocol's model from another.
The protocol Binding helpers fix separate authorization, endpoint and account
snapshots. Host must restrict `AllowedModels` to its actual entitlement and
choose separate credential references/accounts for standard and M Plan use.

All six prices are deliberately **synthetic mechanism-test values**. The
catalog version and model display names say so. `sources.json` records official
schema hashes, the source of capacities/defaults and this limitation. Never
use this catalog to display a real call's cost, M Plan deduction, published
standard API rate or formal support. A sourced M3 price snapshot and each
identity's own live evidence belong to the later catalog release ticket.

`Model.DefaultThinkingLevel` selects the omitted-reasoning sampling label;
it is not an explicit effort and does not alter wire fields. M3 Chat labels
omission high, its Responses/Messages identities label it off, and M3.1
labels it max. M3 maps only off/high; M3.1 requires thinking and maps five
depths. Protocol adapters enforce those constraints after hooks as well.
Messages intentionally ignores the sampling maps.

All models declare text input, a 1,000,000 context metadata bound and the
spec's conservative 131,072 output ceiling. These are not live capacity proof
or an assertion that MiniMax lacks other input modalities. Nothing from this
package enters BuiltinCatalog automatically. See spec R06–R08 and ticket 01.


`PricedM3Catalog()` is a separate Host-owned international standard snapshot:
USD/M input/output/cacheRead .30/1.20/.06, or .60/2.40/.12 above the declared
512000 total-input estimate boundary. Official text only says512k; the exact
integer is conservative project policy, not an official confirmed integer.
The dated pricing overview is authoritative over its stale cache-guide worked
example. No active FX dependency remains. Positive unpriced automatic/1h
cache writes retain known usage and fail estimation; zero is not a free rate.
M3.1 actual token prices and M Plan fees remain unknown. Live candidate reports
keep raw provider usage distinct from explicitly synthetic mechanism Cost.
The catalog is inactive in BuiltinCatalog until three own actual global proofs.

## 9. 验证与阶段事实

| 单元 | 普通验证 | live / race / 压力处理 |
| --- | --- | --- |
| 01 输入交付 | 干净工作区 RED→GREEN；公共证据消费者及其受影响普通包 | 无厂商行为/资格变动时 live 有依据不适用；race 按影响列候选，实施不自动执行；压力按容量影响评估 |
| 02 当前入口 | 引用、锚点、状态及来源/实际输入集合相等性 | 沿用有适用依据的既有事实，不制造新测试结果 |
| 03 脚本分类 | 静态调用关系、分类完整性、历史哈希和活动入口检查 | 不运行历史控制器、生成器或负载 |
| 04 历史追溯 | 指针可读、归档成员/原始哈希、缺失状态；必要只读消费 | 索引若成为执行输入，按行为变更补公共消费者验证 |
| 05 工具迁移 | 公共进程 RED→GREEN、来源选择器/消费者、完整受影响普通包 | 独立评估原生资格；人工 race 另列实际 argv/来源/用例；压力有依据才适用 |
| 06 顶层导航 | 目录集合、引用和唯一状态约束 | 纯展示检查 |

所有实际执行写独立 `.evidence/scratch-artifact-remediation/.../<attempt>/`，保留 argv、数字退出、实际受测 SHA、完整来源/选定输入、日志、manifest/audit 指针及哈希。原件只指向、不复制进 scratch。具体测试名和 case ID 在对应切片实施前从实际发现集合冻结，不能用零匹配或父测试 PASS 代替完整场景。

同一冻结最终来源的普通验证沿用适用回执，避免每个文档收尾都重复全库跑；相关来源/输入变化则重新审查并取得对应新回执。当前资格缺失、人工阶段未执行时，状态明确保持 `release.pass=false`。

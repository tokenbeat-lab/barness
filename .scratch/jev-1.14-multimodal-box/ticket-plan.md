## 拆分与交付

1. **[先重构 TypeSafe 原生快照，保持文本行为](issues/01-typesafe-native-snapshot-prefactor.md)**
   - Blocked by：无。
   - 交付：Host 的既有 Jev 文本请求、合法 Hook 换题和混合答案通过独立 native 快照运行，为新增图片保留清晰边界。

2. **[通过统一引用调用 Decisions 上下文图片](issues/02-decisions-unified-context-references.md)**
   - Blocked by：无。
   - 交付：Host 可用同一 Images 来源和显式 context 引用调用 Decisions，得到正确顺序、复用和发送前拒绝。

3. **[让 Host 核对 Decisions 最终图片身份](issues/03-decisions-final-image-input-metadata.md)**
   - Blocked by：02。
   - 交付：Host 从成功结果得到最终图片 MIME/hash，能识别 Hook 换图及重复图片，失败时不消费半成品元数据。

4. **[接通 Jev JSON 上下文图片闭环](issues/04-jev-context-images-json.md)**
   - Blocked by：01、03。
   - 交付：Host 用已有公共图片与 context 引用，在明确选择实验后通过 Jev 判断并获得最终图片元数据。

5. **[在 Jev State 原位置使用图片引用](issues/05-jev-state-value-images.md)**
   - Blocked by：04。
   - 交付：Host 将图片放入结构化 State 的明确值位置，保留业务结构、精确数值和共享作用域。

6. **[在 Jev 单题说明中使用视觉样例](issues/06-jev-question-instruction-images.md)**
   - Blocked by：05。
   - 交付：Host 把一张图放进某题说明，其他题不收到该局部图片，并能用有序片段混合文字与图片。

7. **[接通 Jev 视觉判定标准并还原公共图例](issues/07-jev-visual-criteria-public-legends.md)**
   - Blocked by：05。
   - 交付：Host 用图片定义 Choice、Bool 或 Score 标准，Score 返回可解释的公共图例引用，完全不依赖 Jev 私有 key。

8. **[通过 Classify 获取 Box 与独立存在性答案](issues/08-jev-box-and-existence-answers.md)**
   - Blocked by：06。
   - 交付：Host 同批询问位置和存在性，得到严格类型化的 Box，并能区分 null confidence、零值及缺失字段。

9. **[验证混合图片调用的并发、资源和撤销](issues/09-mixed-image-runtime-resource-isolation.md)**
   - Blocked by：07、08。
   - 交付：共享 Client 在真实混合分类负载下隔离租户、执行有限资源与重试，并在取消、错误和撤销后释放资源。

10. **[提供 Host 统一图片输入与结果处理示例](issues/10-host-unified-images-examples.md)**
   - Blocked by：07、08。
   - 交付：Host 可运行例子切换两协议、处理视觉图例和 Box，并在受控环境重放成功、拒绝及撤销流程。

11. **[形成 Jev 与 Decisions 各自的候选协议证据](issues/11-candidate-live-protocol-evidence.md)**
   - Blocked by：07、08。
   - 交付：维护者可用有限预算的真实探针分别确认两协议的统一输入映射、最终图片身份及 Jev Box，不混用候选和正式证据。

12. **[独立评估图片分类、存在性和 Box 定位效果](issues/12-independent-visual-quality-evaluation.md)**
   - Blocked by：10、11。
   - 交付：Host 在固定人工标注任务上分别看到 Jev/Decisions 图片分类效果及 Jev Box IoU、缺目标误报，而不把 schema 通过当作准确率。

13. **[纳入 Jev 1.14 目录并建立独立正式支持记录](issues/13-formal-catalog-and-model-specific-support.md)**
   - Blocked by：12。
   - 交付：Host 可发现实际验收过的固定 Jev 1.14 图片/Box 型号，正式支持记录同时保留 Jev 1.13 的身份和历史。

14. **[完成当前目录下的整体发布验收与追溯](issues/14-current-catalog-release-integration.md)**
   - Blocked by：09、13。
   - 交付：维护者取得当前目录/源码下完整且可追溯的验收结论，能明确区分本功能完成、历史阻断和是否可整体发布。

## 依赖原则

- 当前可领取 frontier 是 01、02；按仓库先编号小者的规则先做 01 重构。02 的 Decisions 引用不依赖 TypeSafe 重构，所以不添加虚假阻塞边。
- 04 同时依赖原生快照重构和最终图片来源输出：两者分别由 01、03 提供；03 已传递依赖 02，无需重复列边。
- 05 交付实际 State 图片节点投影；06（说明）与 07（标准/图例）复用它，可独立推进。08 需要 06，以完整验证 Box 自身说明内可见图。
- 09 混合运行时验证、10 Host 示例、11 候选真实协议证据均在 07、08 后可独立推进，不人为串行。
- 12 通过 10 的 Host 流程和 11 的固定候选路线/Hash 形成独立效果证据；13 只有候选协议与效果完整后才能纳入正式目录并采自身 Hash 证据。
- 13 只直接列 12，候选协议票 11 已经经 12 传递阻塞；14 直接列 09、13，公开示例 10 经 12/13 传递阻塞。14 运行既有整体门禁，不在其他票旁边复制一套发布流程。
- 既有 [压力流完整性工单](../barness-ai-thinking-sampling/issues/07-pressure-stream-integrity.md) 仍有独立验收条件；本拆分不修改/关闭它。其状态不阻止新增协议实现，但未解决时总体发布不能 PASS。
- 基本认证/授权、资源上限、最终 Hook guard 与原子结果随每个行为切片一起交付；09/14 是混合与发布证明，不能成为延后基本安全的理由。
- 任何旧接口默认保留是公共合同；内部实现直接替换，不采用与仓库删除原则冲突的兼容 shim 或双写。

02

复制输入与结构校验

产物：这一轮独立持有的输入副本。

chat 先复制 Request 与 options，再校验 Scope、消息和图片。image / classifier 先检查启用策略与已知大小，再复制参考图、Mask、State 和 Questions。

此时没有调用 resolver。非法结构或已知超限在入口结束。

这一阶段的参数与分支

ResourcePolicy未启用 Image / Classifier policy 就拒绝对应操作；图片字节、数量、分类状态和问题大小在此受限。

ReferenceImages / Mask编辑输入要先通过 base64、图片头和 Mask 尺寸检查。

03

Binding 操作校验与类型目录授权

向宿主要 Binding

ResolveBinding(ctx, scope, bindingID)
← 返回 provider、API、endpoint、account、credential ref、版本、允许模型与重试策略。

校验归属与启用状态，确认绑定允许本次 operation，再用 operation + provider + API + model ID 查对应类型目录。

取凭据前，还有 options 与历史处理

chat：Simple 映射 → 协议 options 校验 → prepareTranscript。
image：图片与选项能力。classifier：问题类型能力。

这一阶段的参数与分支

options API必须匹配 Binding.API；选项不能扩大 AllowedModels 或切换 endpoint。

Reasoning：Simple / Full例如 DeepSeek flash 的 Simple medium → high；Full medium 不做同样裁剪。

NativeState / 历史图片同租户、账户与模型的可信状态才重放；其他降级。缺工具结果补错误消息，不执行工具。

展开 options 和历史的分支

Simple MaxTokens 用模型默认或显式值，再裁到估算上下文余量；不裁剪历史。Anthropic budget thinking 另算预算。少量 provider 编码检查仍在第 5 步发生，不能把所有 option 错误都归到凭据前。

历史 SystemMessage 是否合并由 ModelCompat 决定；不接受图片的 chat 模型用文字占位。NativeState 失配会去掉不可信签名、同步工具 ID 并计入降级统计。宿主从持久化载入后，应先校验租户与完整性，再 TrustNativeState。

04

凭据快照与账户一致性

向宿主要 Credential

ResolveCredential(ctx, scope, binding)
← 返回 credential ref、account、key、版本和对应 BindingVersion。

pin → checkSnapshot 对齐 tenant、ref、account 与绑定版本。通过后才记 Resolved=true，固定本轮归属、凭据和目录版本。

产物：一致快照 + 唯一 initialRequest。

这一阶段的参数与分支

一致性冲突结束本轮；宿主可用新的 RequestID 重发新逻辑调用。

Binding.Retry之后的网络重试保持这份快照，不重新解析绑定或重新选 key。

05

构造原生请求与可信 Hooks

将领域消息、工具声明或问题集转换成所选协议 JSON，再经过可信宿主回调。

鉴权合并→OnHeaders→原生 body→OnPayload

Headers：保护字段脱敏展示，不能修改鉴权、Host、账户与缓存亲和字段。
Payload：可保留并修改，或替换工作对象；不能扩大授权。

这一阶段的参数与分支

ToolChoice / CacheRetention影响原生工具选择和缓存字段；SessionID 派生租户与账户隔离的缓存 key。

ReferenceImagesOpenAI：无图走 generations，有图走 edits。Google：都走 interactions，仅 input 内容不同。

choice / score / bool问题类型决定 wire；TypeSafe 的公共 bool 编码为 noul。

展开原生选项、回调与 endpoint 差异

Anthropic thinking / managed effort 会改变 thinking、max_tokens、temperature 和 beta 头。Responses / Chat 的 SamplingParams 按“命名字段 → 型号默认 → 本次参数 → Hook”覆盖；Gemini Simple 忽略 CacheRetention、SessionID、Metadata、TimeoutMs、SamplingParams。

OpenAI image 先固定 generation / edit，OnPayload 不能跨越操作。Google image 可在授权预算内添加参考图；classifier Hook 可改问题集，最终问题集随后成为答案校验契约。

成功 HTTP 响应后执行 OnResponse，输入仅为状态、头与归属，可拒绝但不能改正文。Gemini chat 当前不调用 OnResponse；Google image 会调用。

06

最终授权检查与有界编码

产物：供所有 attempts 复用的冻结请求字节。

对 Hook 的最终 body 重新检查 model、权威字段与资源边界，再编码和限定字节数。image / classifier 会独立解码最终字节，重新校验结构、options、输入与能力。

chat 的最终检查侧重协议授权与边界；不能假定它也做了 unary 同样的完整结构重解码。

这一阶段的参数与分支

N / format / compressionOpenAI 图像响应按最终 N 与格式校验；transparent 需 png/webp，compression 需 jpeg/webp。

Hook 后的 Questions最终键、类型与 criteria 顺序决定答案是否合法。

nil / null / 0不统一：image null 拒绝；chat MaxTokens 的 0 在不同协议上可能省略或发送。完整对照放在参数页。

07

同一套 Attempt / Admission / HTTP / Retry

Attempt ID→本地 + 宿主准入→HTTP→成功：保留许可至解析结束
初始请求失败时

释放许可 → 判断 Binding.Retry → 退避 → 新 Attempt / 重新准入 → 复用冻结请求。

宿主 Admission 收到 tenant / account / attempt，返回 release 或拒绝。准入拒绝不发 HTTP，也不新增 Attempt。

HTTP 成功后，Hook、读取或解析失败直接终结。

这一阶段的参数与分支

Binding.Retry默认不重试；SDK 内置 retry 已关闭。通用规则处理连接失败及 408/409/429/5xx。

Gemini chat 例外无响应连接失败不重试，HTTP 失败不保留重试头；Google image 仍用通用规则。

时间与资源参数总 CallTimeout 包括 resolver；部分协议 TimeoutMs 限制 attempt 到响应头。读取、输出与队列另受宿主策略限制。

ChoiceQuestionInstructions 非空 JSON string/object/array；1–255 个 criteria，值可 string/object/array/null；再与 MaxChoices 相交。Choice 必须是最终 criteria 键；完整同键概率分布、有限 [0,1]、和 1±1e-6；所选项须为最高概率（可并列）；Confidence [0,1]。
ScoreQuestion2–10 个有序 criteria，数组下标是分数；再按 Min/MaxScoreLevels；说明支持结构化 JSON。Score ∈ [0,n−1]、Confidence [0,1]；可选完整 0..n−1 概率；期望误差通常 1e-6，两位小数网格允许有界舍入区间；Legend 需伴概率且等于最终 criteria。
BoolQuestionCriteria 可省略；提供时 true/false 描述必须齐全。wire discriminator 转为 noul。wire noul 概率有限且 [0,1]；公共 BoolAnswer.Probability 是 yes 概率；没有库内阈值判断。

协议成功 ≠ 业务判断

模型输出 choice/score/probability；是否满足业务阈值、自动路由、重审或转人工在宿主层。ResponseModel 是上游实际版本报告，不覆盖授权 ModelID。

用量先登记

input/output 都报告为 complete，缺项 partial，无 usage 为 unreported。TypeSafe 只按 input 费率估价；不是账单。重复或歧义字段拒绝，不使用最后值覆盖。

Gemini chat 的独立重试规则

generateContent 的无响应连接失败不重试；非成功 HTTP 错误不保留 retry headers，因此不使用 x-should-retry 或服务器指定等待时间，按状态与退避决定。

Google image 使用 sendUnary，保留 HTTP header，遵循通用初始请求重试规则。相同 Provider 不代表相同重试路径。

SDK 自带 retries=0。Binding.Retry 默认 MaxRetries=0；配置重试也不会重新读取 resolver、重新选择 key 或重复 headers/payload 回调。

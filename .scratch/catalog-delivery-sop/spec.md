# Catalog CLI 交付规范

将更新 changelog 纳入目录维护 SOP。运行 JSON 必须保留原受测字节，并以真实
Catalog.Version 命名，在统一 `artifacts/catalog/<Catalog.Version>/<批次>/` 下
归集快照、摘要、审阅包、变更说明、验证索引及代码变化/分发判定。

每次同步内置目录必须明确比较的完整基准/目标提交、barness-ai 核心运行代码
和依赖是否变化、示例/测试/工具变更，以及外部 JSON 和内置目录两类使用者的
实际升级/重建要求。结论绑定受测程序和真实验证，不推断最低支持版本。

本次把已完成 Terra 交付按新规范补齐。复用已批准快照与完整 review，保留旧
工作库和所有证据原件的原路径；统一交付索引关联原路径和摘要，不移动或改写
历史测量。源码规定位置的维护源、内置 JSON 和采用基线仍保留。

使用现有 CLI 的显式路径参数，不修改 SDK、加载器、协议、CLI 实现或目录格式。
验证文档引用、全部交付库存/摘要、版本化文件名和原快照字节相等，并通过公共
cataloggen --check 核对。普通受控证据通过完整来源/输入相等性沿用，不重跑厂商、
race、压力或全包测试。

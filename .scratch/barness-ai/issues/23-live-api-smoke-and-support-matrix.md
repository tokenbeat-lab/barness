# 23: 真实 API 冒烟与支持矩阵

**What to build:** 维护者在发布前或 SDK/模型升级后，以同一 Client 对六个首期组合执行真实官方 API 冒烟，结果写入支持矩阵；日常 `go test ./...` 不受影响（spec Testing Decisions §2、§5）。

**Blocked by:** 19, 20, 21, 22

**Status:** ready-for-human

- [x] live 测试需独立 build tag（或显式命令入口）加 `BARNESS_AI_LIVE=1` 双开关；真实 key 仅由 CI secret store 注入到对应 Provider×API 的测试进程，不读开发者默认账号或进程环境回退
- [x] 每个组合执行：短文本 Stream 与 Complete、模型工具调用 → 测试宿主结果 → 下一次生成、首帧后取消，以及受支持模型的推理/签名历史与图片
- [x] 断言结构、关联、终态、非空有效内容与 usage，不断言随机文本全文；限制 token 与调用次数
- [x] 结果仅为 PASS / FAIL / NOT_RUN / UNSUPPORTED：缺 key 为 NOT_RUN，厂商故障为 FAIL/环境故障并在既定预算内重试确认，不改成 skip
- [x] 每次记录模型、SDK 版本、厂商 request ID、耗时、错误类别；输出先脱敏
- [x] 支持矩阵保存 Provider、协议、模型、SDK、测试账户/区域别名、能力与最后通过时间；共享 adapter 不连带标记通过

- **Entry and keys (ADR-0016 决策一):** one process, one combination (`BARNESS_AI_LIVE_COMBO` = `openai-responses`, `anthropic-messages`, `google-gemini`, `openai-chat`, `deepseek-responses`, `deepseek-chat`); the key only from `BARNESS_AI_LIVE_KEY_<COMBO>`; another combination's key in the process, a missing account alias or an unknown combination fails the run (category `config`; such a report is never merged). Models are fixed per combination, with no override. No key: every scenario NOT_RUN. Runbook in `ai/live/doc.go`.
- **Scenarios (决策二):** each combination runs `text-stream`, `text-complete`, `tool-round-trip`, `cancel-after-first-frame`, `reasoning-history`, `image`; the Chat combinations add `usage-position`; DeepSeek Chat adds `forced-tool-with-thinking`, `prompt-cache-long-retention`, `reasoning-level-high/max` on deepseek-v4-pro; DeepSeek Responses adds `reasoning-level-high/max` on deepseek-flash; both DeepSeek combinations add `auth-refused` (a fixed fake key, to record the 401 body and id headers). OpenAI × Chat `reasoning-history` is UNSUPPORTED (no reasoning content to replay). Default models: gpt-5-mini, claude-haiku-4-5, gemini-2.5-flash, deepseek-flash.
- **Outcomes, retries, budget (决策三):** rate_limited/upstream_error/transport/deadline_exceeded are retried once with backoff, then FAIL with `environment`; upstream_auth is environmental but not retried; assertion failures are never retried. 24 logical calls and 4096 output tokens per call per process. evidence gains `Case.Unsupported` (status UNSUPPORTED) and `Run.Record`.
- **Evidence (决策四):** a recording transport keeps redacted request/response captures per scenario (credential headers replaced, key-shaped text masked, response header values allowlisted); `live-report.json` per bundle; a final audit fails the process if the key appears anywhere in the bundle.
- **Matrix (决策五):** merged only through the command; a report changes only its own row (provider/API checked), all-NOT_RUN reports are no-ops, NOT_RUN scenarios keep their last state, FAIL keeps the last pass time, stale reports are refused, and a refused merge leaves the file unchanged. `allPassedAt` is set only by a report that covers every scenario the combination expects, each PASS or UNSUPPORTED (what issue 24's gate reads); a run narrowed with `-run` never sets it. The merge was built test-first in isolation (`merge_test.go`, 15 enumerated failure modes, the last two added after review). Not provoked live: DeepSeek 402/429/503 bodies (recorded only if they occur); no CI exists yet, so per-process injection is enforced by the process check and documented in `ai/live/doc.go`.
- **Verified:** `go test ./...`, `go vet` (with and without the tag) and `-race` on the harness; `go test ./...` unaffected (the tagged files do not build without the tag); with the tag, the switch off/no combination/no key give NOT_RUN for all 46 cases; misconfigurations FAIL. The executing paths were run against a throwaway local TLS fake of DeepSeek Chat (not committed): all 12 scenarios PASS, a 503 retried then PASS, persistent 503 → FAIL `upstream_error` environment after 2 attempts, a silently ignored forced choice → FAIL assertion, the key absent from the bundle, and the report merged into a copy of the matrix (stale re-merge refused, file unchanged).

# 发布验证分为普通阶段与人工选择的 race 阶段

MiniMax 交付中，全程 race 启动76次约耗时5小时9分，多次在已知普通失败后继续运行。采用前置拒绝和顺序失败停止，将普通验证完成与完整发布通过分开；race 在最后由人类明确选择。此决定更新 ADR-0017 的自动收集顺序，保留其纯函数 Evaluate、十项发布门禁、完整包范围、差分/压力、独立 race 证据与逐包审计要求。

`releasegate` 默认 check 阶段完成前置、双 vet、完整普通及证据消费后输出 READY_FOR_RACE，退出2；实际失败退出1。人工执行 race 阶段时指定原 check 目录，工具复核回执、完整编译来源和选定输入，产生独立 race 包后才作完整判定；全部要求通过才退出0。预检退出0只表示外部输入就绪，旧 bundle 的只读重评估仍不能证明命令已运行。

两个阶段之间相关来源、测试、依赖或输入变化使旧普通结果失效。保留原生来源消费者，不缩小 selector 或刷新历史 hash。普通/定向开发验证不自动运行 race；测试风险、审查时机与授权边界由项目策略维护，通用 implement-spec 仅负责遵循项目策略。代价是调用方必须识别等待人工状态；收益是避免已知失败后的昂贵工作，并保留完整发布证据。

# barness-ai 首期由宿主显式提供有限资源策略

原研究确定需要有界资源，但将默认值和可关闭策略留待评审。barness-ai 首期要求本地和云端宿主均在 Client 构造时提供有效的有限资源策略，缺失或非法时拒绝构造；这是本项目新增的选择，用于落实安全默认开启，并使慢消费者、异常 Provider 和并发请求的边界可验收。

## Considered Options

- 核心内置默认值：接入成本低，但目前缺少可重复的负载证据，难以确定适合本地和云端的共同容量与时限。
- 本地无限制、云端再开启：接入方便，但相同库存在不同隐式行为，示例迁移可能漏配保护。
- 显式有限策略：增加宿主装配工作，但配置来源、保护范围和超限行为清晰；首期采用。

## Consequences

- 策略覆盖请求/图片/帧/工具 JSON/错误体/总输出、事件队列字节和条数、租户/进程并发、准入等待及各阶段时限；读取和分配前生效。策略自身不是协议选项，不能由非可信请求取消。
- 构造校验失败属于配置错误；调用期间达到限额产生可识别的 resource_limit 终态。限额内继续遵循 pi，超限路径登记为独立扩展。
- 本地使用也需要配置。过小限制会拒绝合法负载，过大限制会削弱保护；示例必须附有限数值、适用负载、压力验证及调整说明，不能虚构已验证的通用默认值。
- 该决策不改变 maxRetries=0 的有效含义，也不取消 maxRetryDelayMs=0 在原协议策略中“关闭该单项上限”的含义；整次调用仍受有限总截止时间控制。
- 如果以后有可重复压力数据支持通用配置，可通过后续 ADR 提供版本化有限默认配置；保留覆盖与合法性校验，同步验证升级影响和旧配置回退。首期不提供无界模式。

总输出的计量方式及超限终态与重试的关系见 [ADR-0007](0007-barness-ai-output-bytes-and-limit-terminal.md)。准入与各阶段时限的执行位置及终态分类见 [ADR-0008](0008-barness-ai-admission-and-time-limits.md)。行为和证据分别见 [spec 的资源契约](../../.scratch/barness-ai/spec.md#9-资源准入错误与观测) 与 E08。当前仅记录设计决策，没有完成运行时压力验证。

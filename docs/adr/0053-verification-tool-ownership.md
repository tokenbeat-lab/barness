# 验证工具归属与历史源码边界

现行验证代码位于功能scratch目录，Go原生消费者又从旧工单路径执行Jev核验器。目录名称掩盖了活动依赖，迁移若只改命令会遗漏执行来源，或破坏原封存哈希。按用户批准的第5A项，将三类维护能力及进程测试归入根`tools/verification/`，将独立Python协议核验器归入拥有它的`ai/internal/testkit/jevformal/verify_protocol.py`。

## 职责、依赖与数据流

- `run.py`只采集人选定的一条命令；`run_process.py`负责环境、日志、取消/时限；`receipt_files.py`负责有界文件与来源身份；`live_environment.py`只转发原生单路线合同。命令/原生包→不可变attempt，不增调度或授权系统。
- `consume_live.py`只调用已编译原生只读资格消费者，保存真实stdout/stderr/退出及schema2回执；Go releasegate独立核对。清理的scan/state/action仍各自封装，只操作已审批次，测试仅用私有合成目录。
- Jev Python只核验协议结构及原件，不导入Go运行时或拥有当前源码资格；Go原生消费者仍负责完整来源、Classify回放和独立效果。迁移Python保持原字节，不重写其原pin或规则。
- 公共入口为仓库根下的新CLI、现有Go消费者和显式Python进程测试。工具内部导入保持同目录，不建立跨领域工具注册表或新依赖。

## 完整来源与历史

Python采集器和Go只读发布消费者独立枚举`ai/`、`tools/verification/`与go.mod/go.sum，覆盖忽略/未跟踪的执行输入，排除既有文档/缓存。不共享执行代码：独立核验不能信任被核验采集器；增删改及忽略PY通过公共进程相互验证。

Jev原生producer/consumer在原完整Go来源集合之外显式固定新Python路径及实际字节；路径集合变化本身使旧严格来源不适用。新来源取得新普通回执，不能改旧原生map、续期旧live或把离线结果当真实资格。其他暂停/关闭控制器及其历史源码不在迁移范围。

活动旧PY/README路径直接删除，不留wrapper/shim/双写。迁移前18份源码/测试/README原字节、原路径/基址/模式和固定Git保存在[历史索引](../../.scratch/scratch-artifact-remediation/history/phase5-before-20261024/index.json)。历史文档继续按原Git/该索引读原件，快照不从改变后的相对基址执行。第3/4项原分类和回执保持原版本事实，由本次迁移映射解释后继路径。

## 验证、资格与回滚

先以公共CLI/Go受控消费者建立新路径失败与来源漏收场景，再逐切片迁移；复用已有环境隔离、真实输出/退出、取消/超时、最终写失败与清理越界进程场景。普通工具/原生消费者及完整受影响普通包通过后，只报告该来源下实际事实。

源码路径与资格消费者来源改变可能使旧Jev/其他严格原生资格过期，逐路线按原规则记录缺口；用户本次明确禁止付费、race、压力和真实清理，不因迁移补买资格。recovery7继续暂停，完整发布保持false。ADR-0051及原授权/账本/失败原文不变；回滚将实现、调用点、选择器、测试与活动文档成组回退，保留新旧原件，不复活已消费授权。

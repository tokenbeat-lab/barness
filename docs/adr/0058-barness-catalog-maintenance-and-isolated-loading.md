# models.dev 主源、受控接纳与逐模型隔离加载

模型更新频繁，逐型号硬编码目录会延迟可用性。维护者决定以 models.dev 的 `catalog.json?type=all` 为主要维护源，经 barness 映射、人工确认和受控 E2E 接纳后生成自有目录；本期实施维护 CLI 与本地 JSON 加载，线上发布和在线更新另行设计。本决策取代 [ADR-0057](0057-barness-independent-model-catalog.md) 的实施合同，保留其中 Provider 独立内容版本、四维身份、授权独立及固定调用快照的原则。

## 决策与取舍

- 来源采用公共字段规则、Provider 对照、逐条来源关联和人工覆盖。官方文档、公告、模型 API 及自身历史证据补充或核对；models.dev offering 与 canonical 资料不能混用。同一源可对应多个明确确认的 API 条目，不从 SDK 名自动展开协议。
- 维护源与运行类型分开。确定性 CLI 接受外部 AI 或维护者输入，提供 help、dry-run、结构化输出和显式确认。变更先形成冻结候选，经实际受测代码上的受控 E2E 后应用原候选；保留来源、决定、检查及历史，不直接采用上游变化。
- 受控通过只表示本次代码兼容，不表示厂商实测或旧软件兼容。需要代码适配的候选在适配并重验后进入目录，未来与软件配套发布；本期不执行发布。
- 不维护最低软件版本、schema 代次或旧版本测试矩阵。当前版本通过不能推断更早版本通过；用实际受测代码身份追溯证据，而非将其误作历史兼容承诺。
- 本地运行文件沿用 `{hash,catalog}`。加载器严格逐模型解码并复用 ai 约束：成功条目进入现有 `ai.Catalog`，失败条目保留独立内存状态及原因。未知字段不静默丢弃；重复身份的全部冲突记录均失败。无法解析、顶层错误或摘要不符仍拒绝整份文件。零成功时返回完整报告和空可用集合。
- 外层 hash 校验原始 catalog 紧凑字节；有效目录继续使用既有 typed `Catalog.Hash()`。两者可以不同，报告保留两者；不拿过滤结果冒充完整输入。来源版本保持内容版本，合成身份不增加人工全局版本。
- 加载状态固定于启动快照，调用失败不改加载状态、不自动下架或切换模型。Host 展示允许公开的诊断和适当的升级建议；认证、限流或厂商参数错误不能一律判成软件过旧。
- 按 Provider 管理内容版本；生效变更有记录，回退形成新变更。人工覆盖不自动覆盖，缺价不补零，上游 missing/deprecated 不自动下架。初迁移保留现有 118 条定义及其语义，不从实时上游重建覆盖。

隔离加载使旧程序能继续使用它理解的模型，代价是 Host 需要展示“目录已收录但当前不可用”的原因，且不能在加载前保证每条都可执行。独立报告维持现有 `ai.Catalog`/Model 接口；发布前受控接纳与运行时逐条隔离分别解决维护质量和旧程序差异，不互相冒充保证。

## 与已有证据和范围的关系

本决策修订 [ADR-0018](0018-barness-ai-catalog-inclusion-criterion.md) 的目录维护接纳流程，不改写历史测量或已验收型号边界。Kimi、xAI 等现有固定型号约束须作为实际接纳条件评估，不能仅因改用 JSON 就删除或转成通过。协议与模型规则由 ai 保持唯一依据，目录组件不复制第二套能力表。

`ai` 不反向依赖独立目录组件；Host 启动时取得有效目录后仍通过现有 `Config.Catalog` 装配。默认 JSON 与外部 JSON 来自同一维护源，未来替换旧内部字面量而非双写。目录发现或加载成功均不授予 Binding 权限。

当前只授权文档更新；CLI、JSON 加载和逐模型报告尚未实施，受控/真实测试、发布及部署均未由本次定稿执行。完整设计和问答见 [design.md](../../.scratch/barness-ai-dynamic-catalog/design.md)、[discussion.md](../../.scratch/barness-ai-dynamic-catalog/discussion.md)，source schema 研究见 [models-dev-research.md](../../.scratch/barness-ai-dynamic-catalog/models-dev-research.md)。
